# v1.3.0 SAGE-conformant `--auto-id`: Design

- **Date:** 2026-11-15
- **Author:** rocklambros
- **Target version:** v1.3.0 (minor: visible change to generated `document_id` values)
- **Status:** approved for implementation

## 1. Background

SAGE Specification v1.0-RC1 (§3.2, §3.5, Appendix A) requires `document_id`
to match `^[A-Z0-9]+-\d{4}-[A-Z]{2,4}-\d{3,}$`, read as
`{ORG}-{YEAR}-{TYPE}-{SEQ}`. YEAR is the publication year. SEQ is three or
more digits.

`generate_document_id()` in v1.2.2 has three defects:

1. SEQ is `compute_content_hash(body)[:8]`, eight hex characters. Any hex
   letter fails `\d{3,}`, so nearly every generated ID is non-conforming.
2. YEAR is `date.today().year`. The same input converted in a different
   calendar year gets a different ID, which breaks the README's determinism
   promise.
3. `publisher_prefix` and `type_code` from `[document_id]` are never
   validated, so a config value such as `csa` or `GUIDE` produces a
   non-conforming ID with no warning.

## 2. Design

### 2.1 SEQ

Keep the hash input and the 32 bits of entropy. SEQ is
`int(compute_content_hash(body)[:8], 16)` rendered as a zero-padded
10-digit decimal (`2**32 - 1` is 4294967295, ten digits). Two bodies that
share a `content_hash` still share an ID.

### 2.2 YEAR

YEAR comes from the emitted `date` field after `--meta`, `--meta-file`, and
`.any2md.toml` overrides merge. `compose()` therefore generates the ID after
the merge, not inside `_build_fields()`. `generate_document_id()` takes a
keyword-only `year` and never reads the clock. `compose()` also passes its
`content_hash`, so the body is hashed once.

Year extraction from the merged `date`:

- `datetime.date` or `datetime.datetime` (TOML date in a meta file): `.year`.
- `int` in 0-9999 (TOML `date = 2025`).
- `str` that, after stripping whitespace, starts with four Unicode decimal
  digits followed by `-` or the end. This covers `YYYY-MM-DD`, bare `YYYY`,
  the unstripped DOCX `dcterms:modified` value, and PDF dates with
  non-ASCII digits that `str.isdigit()` accepts. `int()` makes the year
  ASCII.
- Anything else raises `ValueError`. The converter reports the file as
  failed and the batch continues, the same path other emission errors take.
  Falling back to the clock would bring back defect 2 without telling the
  user.

### 2.3 Explicit `document_id` wins

When the merged overrides contain a non-empty `document_id`, the generated
ID is not computed and the user's value is emitted unchanged. User-supplied
values are not validated. An empty string counts as unset, so a template
placeholder does not silently turn `--auto-id` off.

### 2.4 Prefix and type_code validation

- `config.validate_document_id_settings(prefix, type_code)` checks prefix
  against `^[A-Z0-9]+$` and type_code against `^[A-Z]{2,4}$`. Non-strings
  fail too. It raises `ValueError` naming the setting, the bad value, and
  the rule.
- `cli.main` calls it after all config layers resolve and before any file is
  read, only when an ID will be generated: `--auto-id` is set and no
  override supplies a non-empty `document_id`. On failure it prints the
  message and exits 1 (usage error). A bad unused value does not block
  conversion.
- `generate_document_id()` repeats the check and raises `ValueError`, so a
  library caller that builds `PipelineOptions` directly cannot emit a
  non-conforming ID. This is a `raise`, not an `assert`, so it survives
  `python -O`. The check runs per document, which costs two regex matches.
  Validating once in `PipelineOptions.__post_init__` was rejected because
  it would also fire when an explicit `document_id` makes the settings
  unused.

## 3. Out of scope

- Hash input changes. IDs stay content-derived.
- Full SAGE JSON Schema validation of emitted frontmatter.
- A legacy hex-ID compatibility flag.
- Validation of user-supplied `document_id` values.
- The `date` field's own fallback (file mtime or today when the source has
  no date). The ID follows whatever `date` the document emits.

## 4. Tests

- Unit (`tests/unit/test_auto_id.py`): regex conformance for defaults and
  CSA/GD, known vector, year from argument, invalid prefix/type_code raise.
- Unit (`tests/unit/test_frontmatter_compose.py` or `test_auto_id.py`):
  compose uses the merged `date` year, a frozen `today` in different years
  does not change the ID, an explicit `document_id` override wins, an
  unparseable date raises.
- Unit (`tests/unit/test_config.py`): validator accepts good values, rejects
  lowercase, too long, digits in type_code, empty, non-string.
- CLI (`tests/cli/test_cli_auto_id.py`): end-to-end regex conformance,
  `--meta date=` drives YEAR, `--meta document_id=` wins, invalid config
  values exit 1 with a message naming the value and rule.

## 5. Compatibility

Every `--auto-id` value changes format. Anyone keyed on v1.2.x IDs must
re-key. CHANGELOG flags this under "Changed", and the upgrading guide gets a
short note. Publishers who need a stable ID across content revisions set
`document_id` explicitly.
